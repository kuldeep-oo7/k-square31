**The user asked (2026-09-23) for simulations of normal / war-news / expiry-eve /
expiry-day markets, checked ON THE PAGE, plus an audit of every calculation and
engine.** Two suites now answer that and run in `npm run check`:
`scripts/simulate-market-scenarios.js` (43 checks; drives the real `build()` with
a controlled clock, phase, books and futures quotes, asserts on the rendered
HTML) and `scripts/audit-probabilities.js` (18 Monte Carlo checks; xoshiro128**,
Brownian-bridge continuous monitoring). Both pass.

**Defects found and fixed, each measured:**

- **BSM given a futures price, everywhere.** `option-pricing.js` line 1: "BSM
  underlying = spot ... BLACK76 = futures price." The screener, `vol-surface.js`
  and `universe-210.js` passed futures/parity forwards to BSM with q=0, double-
  counting carry. TATAPOWER OCT 380 PE @ 12.75: IV 19.10% shown vs 15.58% correct,
  delta -0.619 vs -0.691; 2.75 vol pts mean error over the 40-option shortlist.
  `iv-surface.js` already did it right (model by basis) — that is the pattern.
  Checked against Wikipedia "Black model", LME, Glyn Holton.
- **Forward was yesterday's settlement while the premium was live.** Simulated
  4-June-2024 morning (-5.9%, IV x1.5): old path up to 48.4 vol pts off; fixed
  path 0.11. Screener now takes `forwardFor`; build prices every future in the
  window live; weeklies scale the settled forward by the monthly future's move.
- **F&O ban list six days old; options never checked it.** Committed
  `data/market-coverage.json` dated 2026-09-17 missed LICHSGFIN (banned for
  2026-09-24). Now fetched from NSE (`archives.nseindia.com/content/fo/fo_secban.csv`)
  every build into `.private/cache/fo-ban.json`; universe prefers it; screener
  refuses banned names; page prints the list with its date, red if stale.
- **Headline didn't name the month** ("TATAPOWER 380 PE" vs broker search showing
  SEP/OCT/NOV) and option symbols were always MONTHLY form (wrong for weeklies).
  Now `contractNames()` → "TATAPOWER OCT 380 PE", Zerodha + Angel symbols, expiry
  weekday, exit-by date.
- **Physical settlement.** Stock F&O settles by delivery; delivery margins from
  4 days before expiry (Zerodha, verified). Ledger now TIME_EXITs stock options
  and futures at the close of the 4th weekday before expiry (`exitByDate`);
  index contracts are cash-settled and held.
- **No spread gate**: added `maxSpreadPct: 10` (900 live books: median 3.5%,
  p90 8.5%, worst 38.8%).
- **"Live" meant "today"**: now requires an exchange stamp ≤10 min old, so a
  circuit-breaker halt reads "NOT live at HH:MM".

**Test-suite defects, not desk defects:** `test-contract-identity.js` failed on
junk quotes (IDEA's tight strikes sit on slope −1.005; 40–163%-spread quotes
dragged it to −1.161) and on comparing open interest across sessions (cache held
books from 4 different days). Fixed in the test.

**What the live static build actually runs** (26 project modules, ZERO npm
packages): candlestick-engine, chart-patterns, neural-quant-engine,
unified-quant-scanner, advanced-quant, institutional-calculus, trade-odds,
option-pricing, vol-surface. NOT run: ml-model (boosted trees), recommendation,
trend, upside, market-regime, sentiment-risk, covariance, panel, strategy-lab,
iv-surface, iv-rank. The "neural" engine is a fixed-weight 1-D convolution, not
a trained network.

**Engine health by distribution (2026-09-23):** composite 5–99 (95 distinct),
neural 21–91, Hurst 0.25–0.79, 8 chart patterns (71 non-RANGE). Candlestick
engulfing agrees with Nison's strict definition on 201/210; the 9 extra come
from a deliberate 0.2% tolerance (`prev.close*0.998`) + 10% larger body. Neural
MOTIF label is still lopsided (INSTITUTIONAL_ABSORPTION 159/210, was 201) —
descriptive only, not on the page, not in the score's weighting.

**The number that matters for a trader:** with the futures geometry (+2.5% target,
−1.5% stop from fill) a market with NO edge hits target first exactly 37.5% of
the time (optional stopping: (fill−stop)/(target−stop)). Real ledger on 3,000
no-edge paths: 36.8%. The desk has an edge only if TRACK shows a hit rate above
37.5% (plus costs). See [[k2-ladder-has-no-measured-edge]].

**Simulation limit:** it moves the clock, not the bar history, so from 3+
sessions ahead the universe returns `STALE_DATA_REFUSAL` (correct guard). Put
futures-dependent scenarios within two sessions of the settlement date.
