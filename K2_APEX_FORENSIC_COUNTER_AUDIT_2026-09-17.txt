PART 4 — CALCULATION BUGS IN THE MATHEMATICS
================================================================================

You asked specifically for bugs in the calculations. There were four, all in
institutional-calculus.js, all found by numerical probe rather than by reading.
The existing test suite passed with every one of them present, because it only
checked that numbers fell inside wide ranges. [FIXED — commit 61ce375]

BUG 1 — THE RISK ENGINE REPORTED ZERO RISK ON FAT TAILS. This is the worst one.
The Cornish-Fisher expansion is a third-order approximation and is only a valid
quantile transform while it stays monotone increasing. With skewness clamped to
-3 and excess kurtosis to 10 the polynomial turns over. Measured on a series
containing 9% crash days it produced an adjusted quantile of -0.929, and

    const varPct = Math.max(0, -mean + zCF * stdDev);

quietly converted that into a 99% VaR of exactly 0.00%. The model announced no
risk precisely where the risk was worst, and the Math.max hid it.
    Now: monotonicity guard, empirical tail computed alongside, the more
    conservative reported. Same series: 0.00% -> 11.04%.

BUG 2 — EXPECTED SHORTFALL COULD NOT EXCEED VaR. The Gaussian ES factor is
phi(z)/alpha evaluated at the GAUSSIAN quantile. The code evaluated the density
at the Cornish-Fisher quantile instead, so a fatter tail drove phi(zCF) toward
zero, the factor collapsed, and CVaR fell back to exactly VaR — impossible for
any continuous loss distribution, and again worst exactly where it mattered.
    Now, on a Gaussian control: VaR 2.32% against theory 2.326%, CVaR 2.66%
    against theory 2.665%. Both constants reproduced.

BUG 3 — EVERY INSTRUMENT SHARED ONE LONG-RUN VOLATILITY. omega was fixed at
5e-6 with persistence 0.96, so omega/(1-alpha-beta) pinned every asset in the
universe to 17.75% annualised. A 50%-vol name was told it reverts DOWN to
17.75%; a 7%-vol name that it reverts UP to the same number. Measured before:
0.1775 for a calm series and 0.1775 for a wild one, identical.
    Now omega is solved from the sample by variance targeting: calm 6.6%,
    wild 49.7%.
    The filter loop also stopped one observation short, so the most recent
    return — the most informative shock for a one-step forecast — never reached
    it. A -15% session now moves conditional volatility 0.168 -> 0.751 instead
    of not moving it at all.

BUG 4 — KYLE'S LAMBDA WAS TAUTOLOGICAL. Order flow was signed by the sign of
the very price change it was then regressed on:

    const signedVol = (close >= prevClose ? 1 : -1) * vol;

so the covariance reduced to E[|dP| * volume] and was positive by construction.
Across 200 pure random walks the estimate came back negative ZERO times. Daily
OHLCV cannot recover signed order flow at all — true Kyle lambda needs
trade-level data with a Lee-Ready or tick-rule classification.
    Now it regresses absolute move on volume and declares its own method and
    that it is not Kyle's lambda.

ALSO: skewness and kurtosis divided the third and fourth moments by n while
using the (n-1) sample variance in the denominator. That is not any standard
estimator and biased both toward zero. Now consistent; normal returns measure
kurtosis 2.794 against a theoretical 3.0.

Regression assertions added for every one of these.

PART 8 — THE BLUNT SUMMARY
================================================================================

The infrastructure is real and in places genuinely impressive. The mathematics,
after this session's four fixes, is now correct. The deployment is live.

But before today the desk was displaying a 71.4% win rate that came from seven
rows written by the constructor, computing every quantitative score from a sine
wave, pricing 160 of 210 symbols from a hash or a stale table, and serving its
own database to the open internet.

None of that was a mathematical failure. Every one of those was a failure to
distinguish between a number the system MEASURED and a number the system MADE
UP. That is the single discipline this codebase most needs, and it is worth more
than any additional model: a system that cannot tell you what it does not know
will eventually tell you something false with total confidence.

The fixes in this session are all of the same shape — make the system say
"I don't know" where it previously invented an answer. That is why the
recommendation count is now zero. It should stay zero until real data arrives,
and then it should be earned.
